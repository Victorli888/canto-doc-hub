# Cantonese Wiki — Schema

This repo is an LLM-maintained wiki of spoken Cantonese for daily life, built on the
pattern in [[llm-wiki]]. **You write the wiki. Victor doesn't.** He supplies phrases,
sources, questions and judgment; you do every bit of summarizing, cross-referencing,
filing and bookkeeping.

**The main input is a wish.** Most entries start as a moment where Victor didn't have the
phrase: he froze, fell back to English, or said something stiff. He dumps that moment;
you find what a Hong Kong speaker would actually have said, and file it so it's ready the
next time that moment comes round. The moment is the retrieval cue — always keep it.

Read this file at the start of every session. Read `index.md` before answering anything.

## Who this is for

Victor is **conversational but sounds textbook**. He is not a beginner — do not write
beginner material. No tone drills, no survival phrasebook, no "how to say hello."

What actually moves him forward, in rough priority order:

1. **Final particles.** Textbook Cantonese is mostly real Cantonese with the particles
   stripped out. This is the highest-leverage area.
2. **Register** — which phrasing belongs with friends, at work, with elders, in a shop.
3. **Collocation** — the verb people actually use with that noun, not the one that
   translates cleanly from English.
4. **The stiff/natural contrast** — for any phrase he already knows a formal version of,
   the useful knowledge is what people say *instead*.
5. **Slang and code-switching**, including the English that's genuinely part of HK speech.

His profile, goals and recurring mistakes live in `me.md`. Keep it current — it's how you
know what to emphasize.

## Hard rules

**1. Never invent Cantonese.** A wrong tone number or a made-up usage note gets drilled
into muscle memory and is worse than a gap. If you are not confident about Jyutping, a
nuance, or whether something is actually said:

- **Check the local dataset first: `bin/canto 軟件 訂單`.** words.hk and
  rime-cantonese live in `raw/words-hk/`, so a reading or a "is this word real" check
  is a grep, not a browser. It also carries the entries words.hk hides as unpublished,
  and words.hk's own register labels. See [[words-hk-dataset]] for the two caveats that
  matter — a blank result means *look further*, not *wrong*, and the single-character
  table lists reduced particle forms (ga3) ahead of citation forms (gaa3).
- If it's not there, search: [words.hk](https://words.hk),
  [CantoWords](https://cantowords.com), Wiktionary and
  [Cantonese Sheik](https://cantonese.sheik.co.uk) are the references. Use WebFetch for
  static dictionary pages; a search engine when you need usage frequency rather than a
  reading.
- If it's still unclear, write the entry with `⚠️ unverified` in its Status line, say so
  out loud in chat, and move on. Lint will surface it later.
- Never smooth over uncertainty with confident prose. "I'm not sure whether this is still
  current slang" is a useful sentence.
- Wishes are the riskiest operation, because you are *composing* Cantonese rather than
  checking it. File the **reusable chunk** (the verb phrase, the set expression, the
  particle), verify that chunk against the references, and build example sentences only
  from verified pieces. If you can't tell whether a whole sentence sounds natural, say so
  and mark it `⚠️ unverified`.

**2. Spoken Hong Kong Cantonese, not written Standard Chinese.** 係 not 是, 唔 not 不,
嘅 not 的, 冇 not 沒有, 喺 not 在. Traditional characters. Where the written form differs
and that's worth knowing, note it in the entry rather than silently picking one.

**3. Jyutping only**, with tone numbers: `gaau2 dim6`. No Yale, no ad-hoc English
phonetics. Changed tones are written as `wui6-2` when the entry is worth that precision.

**4. File, don't chat.** Anything worth knowing goes into a page. If a good answer only
exists in the conversation, it is lost — that's the failure this wiki exists to prevent.

## Structure

```
index.md          catalog of every page — read this first, update on every write
log.md            append-only timeline
me.md             level, goals, weak spots, recurring mistakes
review.md         regenerated by Review; never hand-edited
inbox.md          Victor's dump of wished-for moments — the one file he writes in
raw/              immutable sources. Read, never modify. raw/assets/ for images.
  words-hk/       local reference datasets, gitignored. `bin/canto --fetch` restores.
bin/canto         offline Jyutping + definition + register lookup. Rule 1's first stop.
wiki/
  phrases/        pages by SITUATION — work-small-talk.md, ordering-food.md, …
  patterns/       sentence patterns & grammar — final-particles.md, …
  vocab/          thematic sets where a list beats prose — measure-words.md, …
  pronunciation/  lazy-sounds.md, tone-sandhi.md, …
  register/       politeness, slang, formality, English code-switching
  strategies/     one page per strategy + what-works.md synthesis
  sources/        one summary page per ingested raw source
```

Create folders and pages when there is content for them. **Never create empty stubs** —
orphan pages are exactly what Lint exists to delete.

Phrases are **H3 blocks inside situation pages**, never one page per phrase. Blocks stay
greppable, stay linkable (`[[work-small-talk#搞掂]]`), and keep related phrases adjacent
where the contrast notes actually land. When a page passes ~25 entries, split it by
sub-situation.

## The phrase block

Every phrase anywhere in the wiki looks like this:

```markdown
### 搞掂 — done / sorted
- **Jyutping:** gaau2 dim6
- **Literal:** handle–settled
- **Use:** A task is finished. Everywhere at work and with friends. 「搞掂喇!」 = "Done!"
- **Register:** casual; fine at work, not in formal writing
- **Contrast:** 完成 (jyun4 sing4) is the written/neutral "complete" — saying it out loud
  is one of the things that sounds textbook
- **Status:** learning · captured 2026-11-01 · heard from a coworker
- **See also:** [[final-particles]], [[work-small-talk]]
```

Required: **Jyutping**, **Use**, **Register**, **Status**. Wished entries also require
**Moment**.
Optional, when they add something: **Literal**, **Contrast**, **See also**, **Example**.

**Moment** is the situation he needed the phrase in, in his own words, kept short, placed
straight after the heading:
`- **Moment:** telling the cha chaan teng waiter I'd ordered the drink cold, not hot`.
It's what makes the entry findable from memory, and it's the scene Practice replays.
When he tells you what he actually said, it goes in **Contrast** as `I said: …`, followed
by why it landed stiff. An entry wished for again gets the new moment added, not a
duplicate block.

**Contrast** does the heavy lifting for Victor's goal. Reach for it often.

**Status** has exactly four values and a trail:

| Value | Means |
|---|---|
| `new` | Captured. Not used yet. |
| `learning` | Actively trying to use it. |
| `active` | Has used it in real conversation at least once. |
| `solid` | Comes out without thinking. Stops appearing in review. |

Practice moves `new` → `learning`. Only real conversation moves anything to `active`.

Format: `Status: learning · captured 2026-11-01 · heard at dim sum`
For wishes, `wished` replaces `captured`: `Status: new · wished 2026-11-02 · at the bank`.
Add `· ⚠️ unverified` when rule 1 applies. Add `· source: seed` for entries you seeded
rather than ones he captured.

## Operations

### Wish — the primary one

Victor dumps a moment where he didn't have the phrase. No format required; each of these
is a complete request:

```
wanted to tell the waiter the soup was too salty
coworker asked if I'd finished the deck, I said 我已經完成咗 — felt stiff
taxi: "just stop anywhere here" — froze, said it in English
```

1. Pull out the **situation**, the **intent** (what he meant, including tone: joking,
   apologetic, firm) and **what he actually said**, if he says.
2. Find what a Hong Kong speaker would say there. Usually one version; two only if
   register genuinely splits it (friend vs. shop staff, say). Apply rule 1. This is
   where it bites.
3. Identify the **reusable chunk**, the part that will come up again in other moments.
   That's the H3 heading. The full sentence for this moment goes in **Example**.
4. Check whether the chunk is already in the wiki. If it is, add the new moment to that
   block instead of duplicating it. A phrase wished for twice is a strong signal; say so.
5. File by **situation** (where the moment happened), with **Moment**, and with
   `I said:` in Contrast if he gave it. Then Capture steps 4–6: cross-link, index, log.
6. If what he said matches a weak spot in `me.md`, or is the third time for the same
   mistake, update `me.md`.
7. Reply short: the natural version with Jyutping, why his version was stiff, and the
   one thing to notice (usually a particle or a verb choice).

Several wishes in one message → one pass, one log line.

### Process inbox

`inbox.md` collects wishes when he's away from a session (phone, Obsidian mobile).

1. Run **Wish** on every item, batched.
2. Delete each processed item from `inbox.md`. Leave any item you couldn't resolve, with
   a one-line note under it saying what you need from him.
3. One log line: `## [date] wish | inbox, 6 items → [[ordering-food]], [[taxis]]`.

### Practice

He says "practise", or "practise taxis". This is where entries turn into speech.

1. Pick 3–5 entries: `learning` first, then the oldest `new`. Restrict to a page or
   situation if he names one.
2. For each, replay the **Moment**: set the scene in a line or two, in Cantonese, and
   let him respond. Stay in character and don't hint the target phrase.
3. After each response: if he used the target naturally, say so. If not, give the
   natural version and one line on the difference.
4. Afterwards, move practised entries from `new` to `learning` and append
   `· practised <date>` to the trail. New mistakes go to `me.md`.
5. Log: `## [date] practice | 4 entries, [[taxis]], [[ordering-food]]`.

Rule 1 applies to your lines in the role-play too. Keep them simple and certain.

### Status

"I used 囉 today" → `active`, append `· used <date> <where>`. "That one's solid now" →
`solid`. Log as `status`.

### Capture — a phrase he heard

Victor mentions a phrase in chat. This is how most knowledge arrives; make it frictionless.
He should be able to type 「搞掂」 and nothing else.

1. Confirm meaning, Jyutping and register. Apply rule 1 — search when unsure.
2. Choose the page. Prefer an existing one. If none fits, create the situation page and
   say so in your reply. Don't stop to ask; he'll redirect if he disagrees. Asking per
   page stalls a batch of wishes.
3. Write the block in the canonical format, in the right place on the page (group by
   sub-topic, not by date added).
4. Cross-link **both directions** — add the `See also` here, and add a link back from the
   pages you referenced.
5. Update `index.md` if the page is new or its one-line summary has drifted.
6. Append to `log.md`.
7. Reply in chat with the nuance that's worth knowing — the contrast, the particle it
   usually travels with, the register trap. Short. This is the part he actually reads.

If he gives several phrases at once, batch them: one pass, one log entry.

### Ingest

A source lands in `raw/` — a clipped article, a video transcript, lesson notes, a
screenshot of a chat.

1. Read it. Discuss the takeaways with him before filing.
2. Write a summary page in `wiki/sources/`, with a frontmatter link to the raw file.
3. Fan the phrases out into the right situation and pattern pages as normal blocks, each
   with `· source: [[the-source-page]]` in its Status trail.
4. Update `index.md`, append to `log.md`.

Prefer one source at a time with him involved over silent batch ingestion.

### Query

He asks a question.

1. Read `index.md` first, then drill into the pages it points to.
2. Answer with citations — link the pages you used.
3. **Offer to file the answer.** A good comparison, a list he asked for, a distinction you
   drew — these are wiki pages, not chat messages. Ask, then file.

### Review

Regenerate `review.md` from scratch. Never hand-edit it. Sections:

- **Stalled** — `new` for more than ~2 weeks. Collected and never touched.
- **In flight** — `learning`, oldest first.
- **Never used** — `new` or `learning`, captured over a month ago, never reached `active`.
- **Unverified** — every `⚠️ unverified` entry, so they can be resolved in one pass.
- **Ready to retire** — `active` entries old enough to probably be `solid`; ask him.
- **Moments that keep coming back** — situations with the most wishes in the last month.
  Those are the pages worth deepening and the scenes worth practising.

Collecting phrases and never speaking them is the way this wiki fails. `review.md` is the
honest mirror — write it plainly, don't soften the counts.

### Lint

Periodic health check. Report, propose, then fix on his nod:

- Contradictions between pages.
- The same phrase filed in two places — merge, leave a link.
- `⚠️ unverified` entries — resolve them with a search.
- Orphan pages with no inbound links; pages missing from `index.md`.
- Pages past ~25 entries that should split.
- Concepts referenced repeatedly but with no page of their own.
- Gaps worth filling — and suggest the questions and sources worth chasing.

## log.md format

Append-only. One line per operation, consistent prefix so
`grep "^## \[" log.md | tail -5` works:

```
## [2026-11-02] wish | soup too salty, stop here → [[ordering-food]], [[taxis]]
## [2026-11-01] capture | 搞掂, 收工 → [[work-small-talk]]
## [2026-11-01] ingest | "HK slang explained" → [[wiki/sources/hk-slang-explained]]
## [2026-11-01] query | softening requests → filed [[softening-and-politeness]]
## [2026-11-01] lint | 3 unverified resolved, 1 page split
```

Verbs: `wish` · `capture` · `practice` · `status` · `ingest` · `query` · `review` ·
`lint` · `meta`.

## Scaling note

`index.md` is the retrieval mechanism and it's sufficient well past 100 pages. When it
stops being enough, the next step is [qmd](https://github.com/tobi/qmd) — local hybrid
search over markdown, with a CLI and an MCP server. Don't build search before then.

`CLAUDE.md` is meant to co-evolve. When a convention here turns out to be wrong, or a
